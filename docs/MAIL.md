# Почта «Нимба Мира» — как отправить письмо игрокам

В игре есть вкладка **«Почта»** (конверт ✉ в шапке рядом с золотом, плашка в Лагере и пункт в меню «Ещё»).
Игра работает без интернета, но когда у игрока есть связь, она скачивает «ленту писем» —
файл [`mail/inbox.json`](../mail/inbox.json) с сайта игры (GitHub Pages). Новые письма из ленты
кладутся в ящик героя, подарки игрок забирает кнопкой «Забрать».

- Каждое письмо получает **каждый герой один раз** (по `id`). Повторная загрузка ленты, перезапуск игры,
  перевод часов на телефоне — подарок второй раз не выдаётся.
- Без интернета игра не ждёт: в ящике остаются уже полученные письма, а внизу видно
  «Нет связи — новые письма придут, когда появится интернет».
- Сама игра тоже пишет письма (работает офлайн): приветствие от Ильвары после пролога
  и награда за каждую пройденную арку (10 глав).

## Как отправить письмо — способ 1: в браузере на GitHub (без программ)

1. Откройте https://github.com/nikitadob123-bit/anime-rpg/blob/main/mail/inbox.json
2. Нажмите карандаш ✏️ («Edit this file»).
3. Внутри `"letters": [ … ]` после последнего письма поставьте запятую и вставьте новое письмо, например:

```json
    {
      "id": "halloween-2026",
      "from": "Администрация",
      "title": "Ночь Тыкв в Хельморе",
      "body": "Король Демонов!\n\nВ честь праздника — подарок от Администрации.",
      "date": "2026-10-31",
      "expires": "2026-11-07",
      "gifts": { "gold": 1000, "cons": { "pot_hp2": 5, "food_pie": 2 } }
    }
```

4. Внизу нажмите **«Commit changes…»** → ещё раз **«Commit changes»**.
5. Подождите **~1 минуту** (GitHub Pages обновляет сайт). Всё: письмо придёт игрокам, когда они
   откроют игру или вкладку «Почта» с интернетом (игра также сама проверяет почту раз в 15 минут).

Проверить, что сайт уже обновился: откройте https://nikitadob123-bit.github.io/anime-rpg/mail/inbox.json —
там должно быть новое письмо.

> ⚠️ **id должен быть новым**, ни разу не использованным: латиница, цифры, `-`, `_`, `.` (например `event-2026-11-01`).
> Если поставить старый id, письмо не придёт тем, кто уже получил письмо с этим id.
> Ошибку в JSON (лишняя/пропущенная запятая, кавычки) игра переживёт — просто пропустит ленту или битое письмо.
> Проверить файл можно командой `node tools/mail.js check` (см. ниже) или на https://jsonlint.com.

## Способ 2: командой (если репозиторий скачан на компьютер)

```bash
node tools/mail.js add --title "Ночь Тыкв в Хельморе" --body "Король Демонов!\n\nПодарок от Администрации." --gold 1000 --item pot_hp2:5 --item food_pie:2 --days 7
git add mail/inbox.json && git commit -m "Письмо: Ночь Тыкв" && git push
```

Команда сама придумает уникальный `id`, проверит предметы и сохранит письмо в `mail/inbox.json`.

| Команда | Что делает |
|---|---|
| `node tools/mail.js add …` | добавить письмо (параметры ниже) |
| `node tools/mail.js list` | показать все письма в ленте |
| `node tools/mail.js remove <id>` | убрать письмо из ленты (у получивших оно останется) |
| `node tools/mail.js check` | проверить файл на ошибки |
| `node tools/mail.js ids` | список всех id предметов |

Параметры `add`:

| Параметр | Пример | Смысл |
|---|---|---|
| `--title` | `--title "Привет"` | заголовок (обязательно) |
| `--body` | `--body "Строка 1\nСтрока 2"` | текст; `\n` — новая строка; `{name}` — имя героя |
| `--from` | `--from "Ильвара"` | отправитель (по умолчанию «Администрация») |
| `--gold` | `--gold 500` | золото |
| `--xp` | `--xp 300` | опыт героя |
| `--sp` | `--sp 1` | искры Нимба |
| `--item` | `--item pot_hp2:3` | предмет `id:количество` (расходник, материал или подарок Свите); можно несколько раз |
| `--gear` | `--gear sword:epic` или `--gear ring:3:20` (3 = Уникальный) | снаряжение `base:редкость[:уровень]`; без уровня — по уровню героя |
| `--unique` | `--unique eden_light` | уникальный предмет по id (единственный способ выдать «Концептуальный»; `--gear sword:8` запрещён) |
| `--to` | `--to NM-7K3Q9P` | адресное письмо: только игрокам с этими кодами (через запятую или несколько `--to`) |
| `--gear-name` | `--gear-name "Клинок вестника"` | своё имя для вещи из `--gear` |
| `--days` | `--days 7` | срок: письмо можно забрать 7 дней (включительно) |
| `--expires` | `--expires 2026-12-31` | срок до даты (включительно) |
| `--date` | `--date 2026-11-01` | дата письма; если в будущем — письмо придёт в этот день |
| `--min-level` | `--min-level 10` | только героям от 10 уровня (остальным придёт, когда дорастут) |
| `--min-chapter` | `--min-chapter 5` | только тем, кто прошёл 5 глав |
| `--new-players` | | только героям, созданным после даты письма |
| `--created-before` | `--created-before 2026-10-01` | только «старым» героям (компенсация) |
| `--id` | `--id event-1` | свой id вместо автоматического |
| `--dry-run` | | только показать письмо, не сохранять |

## Формат письма

| Поле | Обязательно | Пример | Смысл |
|---|---|---|---|
| `id` | да | `"launch-2026-10"` | уникальный id (латиница, цифры, `-_.`, до 64 символов) |
| `title` | да | `"Добро пожаловать!"` | заголовок |
| `from` | нет | `"Администрация"` | отправитель |
| `body` | нет | `"Текст\n\nЕщё абзац"` | текст письма, `\n` — перенос строки, `{name}` — имя героя |
| `date` | нет | `"2026-10-06"` | дата; будущая дата = письмо придёт в этот день |
| `expires` | нет | `"2026-10-13"` | до какого дня (включительно) можно забрать подарок; после — «Срок истёк» |
| `to` | нет | `["NM-7K3Q9P"]` | коды игроков (вид `NM-XXXXXX`, регистр не важен); письмо получат только они. Без `to` — всем |
| `conditions` | нет | `{ "minLevel": 10 }` | условия: `minLevel`, `minChapter`, `newPlayersOnly` (true), `createdBefore`, `createdAfter` (даты) |
| `gifts` | нет | `{ "gold": 300 }` | подарки (ниже). Без `gifts` — просто письмо-новость |

## Подарки (`gifts`)

| Тип | Пример | Что даёт |
|---|---|---|
| `gold` | `"gold": 500` | золото 🪙 |
| `xp` | `"xp": 300` | опыт героя (может поднять уровень) |
| `sp` | `"sp": 1` | искры Нимба ✦ |
| `cons` | `"cons": { "pot_hp2": 3 }` | расходники (зелья, склянки, еда) |
| `mats` | `"mats": { "ore_fe": 5 }` | материалы |
| `presents` | `"presents": { "flowers": 1 }` | подарки для Свиты |
| `unique` | `"unique": "eden_light"` (или массив) | уникальный предмет с фиксированными статами. Не выпадает, не продаётся, не куётся — только так |
| `gear` | `"gear": [{ "base": "sword", "rarity": "epic", "il": 20, "nm": "Клинок вестника" }]` | снаряжение: `base` и `rarity` обязательны, `il` (уровень 1–100) и `nm` (имя) — нет. До 10 вещей |

Пример со всем сразу:

```json
"gifts": { "gold": 1000, "xp": 500, "sp": 1, "cons": { "pot_hp2": 3, "el_atk": 1 }, "mats": { "ing_fe": 5 }, "presents": { "wine": 1 }, "gear": [{ "base": "ring", "rarity": "rare" }] }
```

Редкость (`rarity`) — число или имя:

| Число | Имя | Редкость |
|---|---|---|
| `0` | `common` | Обычный |
| `1` | `uncommon` | Необычный |
| `2` | `rare` | Редкий |
| `3` | `unique` | Уникальный |
| `4` | `epic` | Эпический |
| `5` | `legend` (или `legendary`) | Легендарный |
| `6` | `mythic` (или `myth`) | Мифический |
| `7` | `divine` (или `god`) | Божественный |

`8`+ (Концептуальный, Исток, До существования) через `gear` не выдаются: письмо с ними не пройдёт проверку.
Концептуальные вещи существуют только как уникальные предметы — подарок `unique`.
С версии 2.10.0 числа сдвинулись: раньше `3` был Эпическим, `4` — Легендарным; теперь это `4` и `5`.
Надёжнее писать имя (`"rarity": "epic"`). Чем выше редкость, тем больше основных статов, линий характеристик
и аффиксов; с Уникального появляются особые свойства (✦ уникальное, ✸ мифическое, ☀ божественное).

## Уникальные предметы и личные письма

Уникальные предметы (`node tools/mail.js ids` — список):

| id | Предмет | Редкость |
|---|---|---|
| `eden_light` | Свет Эдема (меч) | Концептуальный |

Код игрока (`NM-XXXXXX`) создаётся один раз на героя и виден во вкладке «Почта» (внизу) и в «Меню» → «Сохранения», с кнопкой «Копировать».
Отправить меч одному игроку:

```
node tools/mail.js add --title "Свет Эдема" --body "Этот клинок — ваш." --unique eden_light --to NM-XXXXXX --id eden-NM-XXXXXX
git add mail/inbox.json && git commit -m "Письмо: Свет Эдема" && git push
```

Подарок письма выдаётся один раз (по `id`), поэтому повторная доставка меч не продублирует.

## Как это устроено (для разработчика)

- Лента: `mail/inbox.json` (`{ "letters": [ … ] }`), раздаётся GitHub Pages. Игра скачивает её с `?t=<время>` и `cache: 'no-store'`;
  service worker пропускает `mail/*` мимо кэша. Последняя скачанная лента хранится в `localStorage['arpg.mailfeed']`.
- Когда: при запуске, при входе в игру, при открытии «Почты» (и кнопкой ⟳), при появлении сети, раз в 15 минут.
- Логика — `js/mail.js` (`RPG.M`: `parseFeed`, `deliver`, `claim`, `claimAll`, `localLetters`), UI — `js/ui-mail.js`.
- Состояние — в слоте героя: `slot.mail = { list, seen, claimed, arcBase }`. `seen[id]` — письмо уже доставлено,
  `claimed[id]` — подарок выдан; оба остаются и после удаления письма, поэтому ни повторная лента, ни часы не дают дублей.
  Старые сохранения получают пустой ящик при загрузке (формат сохранения v5 не менялся).
- Тесты: `node test/mail.js` (входит в `npm test`), `node tools/e2e-mail.js`.
